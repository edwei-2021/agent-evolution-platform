# Instructions for AI maintainers

Before changing stage M acceptance, runtime discovery, workflow deadlines, or test supervision, read `docs/ai-maintenance-lessons.md` and the relevant section of `docs/intermediate-m.md`.

- Start from the first failed leaf case and its exact source/report identity. Separate observed evidence from hypotheses.
- Audit later unexecuted cases for the same dependency, cold-cache, deadline, and cancellation risks before publishing a fix.
- Keep state reads independent of optional SDK imports and model work. Readiness observations never authorize dispatch; pinned checks belong in configuration freezing.
- Derive enforcement limits from serial work, including independent verification and cleanup. Human duration estimates do not extend hard deadlines.
- Prove slow/cold/expired-cache behavior and real failure paths locally. A fast local pass does not establish a WSL pass.
- Use exact case selection or the scoped M7 continuation runner when diagnosing a failed tail. Never silently promote historical passed evidence to acceptance of changed source.
- Preserve per-case evidence, failure logs, source hashes, and bounded unattended cleanup. Unknown case IDs and empty selections must fail.
- Respect existing publication authorization. Do not ask the user to repeat long upstream checks just to discover independent downstream defects.

- For every affected integration case, expand its subprocess/test-discovery graph to leaf commands. Record the expanded module list and every enclosing execution and cleanup deadline; checking only the top-level test file is insufficient.
- A wildcard test selector requires an audited manifest. Scope growth must update its frozen budget and regression proof.
- Before reporting a deadline repair complete, exercise a controlled child beyond the former child AND parent limits, verify process-group cleanup, and confirm temporary run logs survive into the exported support ZIP.

- Convert every timing lesson into a resource-count invariant: GEPA requires immediate rollout verification, evaluator replay and independent reviewer replay. Validate counts against real evidence; a timeout threshold assertion alone is insufficient.
- Audit successful-tool branches and post-completion verification/approval replays separately. Exact-case parent limits must contain these costs plus cleanup; split aggregate model modules before the parent cap.
- Strict continuation runs only the failed case and unexecuted tail. Do not append already passed frontend/API/harness checks; run only directly affected new regressions separately.
- Treat terminal-state publication as an observable resource contract: finish owned cleanup and serialize final persistence/slot release with status reads. Prove it with a paused finalizer, including success/failure/cancellation; avoid speed-dependent polling assertions.

- Heartbeat arithmetic must compare values in the same clock domain. Prove clock-origin invariance and a real quiet child below its normal estimate through both supervisors; verbose slow tests do not qualify quiet paths.
- Pair heartbeat success with silent-supervisor failure and an independent hard-deadline failure. Supervisor output never proves model progress or extends a hard deadline. Keep pre-frame startup separate from authenticated-step silence.
- Exercise the actual failed/interrupted test teardown, not only a standalone evidence-copy helper: close owned resources, preserve logs, delete the temporary source, then verify bounded/redacted ZIP export.

- Validate semantic variants of promised syntax, not only the one spelling generated by mocks. Pair allowed equivalents with rejected neighboring forms, and keep model-facing errors consistent with the grammar. Trace the earliest rejected tool before blaming a terminal SDK limit.
- A shared evaluator-policy change must cover write mediation, independent evaluation, reviewer replay, GEPA fixtures and copied image payload. Preserve historical outcomes and require a new immutable image for Docker-backed execution; label scripted replay separately from a new real-model run.
- Before changing accepted Python syntax or tool validation, also read `docs/repair-raise-followup.md` for the shared-policy and semantic-variation contract.

- Before changing diagnostic logging, read `docs/runtime-diagnostics.md`. Logs must preserve request phase and original failure evidence, remain bounded/failure-isolated, omit raw model bodies from support archives, and never add probes, retries or deadline extensions.

- Before changing repair completion, read `docs/repair-completion-followup.md`. Prove the visible-pass-to-summary transition with a repeating-tool model, source mutation and a noncompliant server. Freeze provider-specific finalization policy, count the summary within existing caps, and never convert `max_iterations` or a visible-only pass into independent success. Verify exported diagnostics through the actual ZIP/redaction consumer.

- Before changing GUI benchmark profiles or source/Skill history, read `docs/gepa-workload-and-change-history.md`. Assert the actual submission payload and count independent final rollouts plus all three verification passes. Keep time estimates distinct from enforced limits. History reads must not dispatch models, rerun scoring, fabricate missing decisions, or confuse a source repair with Skill evolution; retain failed and unchanged attempts and preserve open details during polling.

- Before changing question CRUD, challenge policy or bank-profile evaluation, read `docs/python-challenge-bank.md`. Keep references out of model fixtures, freeze dataset revisions, validate genuine faulty starts, prevent related groups crossing splits, and reconcile difficulty/aspect totals with trusted final scores. Freeze hashed source before integration checks; do not edit it while those checks run.
