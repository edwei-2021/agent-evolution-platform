# 如何判讀 GEPA 的實際演化成果

開啟 GUI 的「GEPA 技能最佳化」，頁面上方的「實際演化成果」以目前選取的 Run 為準。可在「近期 GEPA 實驗」點選舊 Run；不需要再次執行模型。更新程式並重新整理頁面後，既有完整結果也會使用新摘要。

## 三項結論分開看

| 項目 | 代表意義 |
| --- | --- |
| 執行流程 | `completed` 表示執行、獨立評估與審查完成，不保證技能有改善。 |
| 實際演化成果 | 選定 Skill 必須與基準不同、獨立驗證成功題數增加，而且最終測試不退步，才顯示「已驗證改善」。 |
| 版本啟用狀態 | 通過門檻仍須人工核准。核准並啟用只影響未來 GEPA 實驗；目前使用其他版本時會另外標示。 |

演化的是 Python 修復 Skill 的提示詞本文，並非訓練模型權重。下方並列顯示基準與選定 Skill，方便檢閱具體內容。

## 分數與改善幅度

摘要分別列出「獨立驗證」與「最終測試」的基準、選定 Skill、成功題數差與百分點差。例如 1/2（50%）變成 2/2（100%），改善為 +1 題、+50 個百分點。以該 Run 凍結的資料分割與證據計算，不使用目前輸入框設定。

若基準與選定 Skill 都是 2/2 和 4/4，且本文相同，結論為「未產生新 Skill・沿用基準」，改善幅度為 0。這代表本輪樣本未量到新增效果；不能推論模型在其他資料上也都滿分。

搜尋驗證達到滿分時，固定版本 GEPA 的完美分數略過機制可能讓候選提案數為 0。即使產生多個提案，最終仍可能選回基準。提案數、rollout 數、模型呼叫數是工作量，不能當成改善證據。同一 Skill 重跑造成的分數波動也不算新技能演化。

## 不完整或未通過的結果

尚在執行、失敗、中斷、取消，或缺少完整審查的 Run，不會顯示已確認的改善，也不開放核准。已保存的中途評估只作為快照供檢閱。連線中斷時會標示保留的歷史結果。

候選本文有變更，但驗證未改善或最終測試退步時，保留分數與本文供檢查，維持現行版本。通過門檻後若目前基準已經換成其他版本，也不能直接核准舊基準的實驗。

Smoke 與 Full 皆是分組的合成 Python 修復題，證據範圍限於該輪樣本。資料集匯入與跨資料集效果驗證仍是後續工作；增加呼叫預算或反覆跑同一組滿分題，不會自行產生更強的效果證據。

## 維護檢查

結果展示必須同時確認 Run 已完成與審查通過，並分開呈現 Skill 變更、分數改善及版本啟用。歷史選取、保留快照、輸入框取得焦點時的 polling，都必須使用同一 Run 的證據。顯示修正不改評測器、評分或版本核准門檻，也不觸發新的模型請求。

本次展示回歸使用合成結果覆蓋零改善、驗證改善、最終測試退步、同本文分數波動、未完成審查、核准／回復與歷史選取；另檢查輸入框保持焦點時的成果更新。這些是 UI 回歸證據，不能當成新一輪實機演化成效。
